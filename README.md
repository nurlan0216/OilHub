## A. Первое развёртывание с нуля

**1. Таблица и сервер (Apps Script)**
1. Создайте Google Таблицу «OilHub».
2. Расширения → Apps Script. Вставьте весь `Code.gs`. Добавьте второй файл проекта (+ → Скрипт) `migrate.gs` и вставьте его содержимое. Сохраните.
3. Выберите функцию `migrate` → «Выполнить» → разрешите доступ. `migrate()` сама вызывает `setup()`: создаёт все листы и колонки, ничего не удаляя. Запускать можно повторно.
4. Создайте администратора. Временно добавьте внизу `Code.gs`:
   `function runAdmin(){ return setAdmin('admin','ВАШ-НАДЁЖНЫЙ-ПАРОЛЬ','Имя'); }`
   выполните `runAdmin`, затем **удалите эту функцию вместе с паролем**. Пароль не короче 8 символов.

**2. Script Properties** (Apps Script → «Настройки проекта» → «Свойства скрипта»)

| Свойство | Что это | Кто задаёт |
|---|---|---|
| `TG_TOKEN` | токен бота от @BotFather | вы, только здесь |
| `TG_CHAT_ID` | общий чат Telegram (можно не задавать здесь, а сохранить в админке) | вы или админка |
| `SALT` | соль паролей | создаётся сама в `setup()`; **не меняйте и не удаляйте**, иначе все пароли перестанут подходить |
| `BACKUP_FOLDER`, `BACKUP_KEEP`, `BACKUP_LAST`, `BACKUP_ERR` | папка и число копий, последняя копия и ошибка | система (резервная копия) |
| `TG_Q`, `TG_LAST_ERROR` | очередь неотправленных уведомлений и последняя ошибка | система |
| `MEDIA`, `LABEL_SEQ` | папка загруженных картинок, счётчик внутренних кодов этикеток | система |

Токен нельзя помещать в таблицу, HTML, JavaScript и репозиторий. Все права проверяет сервер.

**3. Веб-приложение**
1. Развернуть → Новое развёртывание → Веб-приложение → «Выполнять от: меня», «Доступ: все». Скопируйте URL `…/exec`.

3. При первом запуске функций, которые пишут на Drive и ходят во внешние сервисы (`installBackup`, `testTelegram`), Google попросит дополнительные разрешения: подтвердите их.

**4. GitHub Pages**
1. Загрузите все файлы в репозиторий (структуру папок не менять) → Settings → Pages → Branch `main` / root. Адрес: `https://<логин>.github.io/<репозиторий>/`.
2. **Замените адрес сайта**, если он не `https://nurlan0216.github.io/OilHub/`: он прописан в `index.html` (`og:image`, `og:url`, `canonical`), `sitemap.xml` и `robots.txt` (`Sitemap:` и пути `Disallow`).
3. Нужен HTTPS (GitHub Pages даёт его сам): без него не работают установка приложения и service worker.

**5. Первый вход**
1. Откройте `admin.html`, войдите. В разделах «Категории», «Товары», «Услуги», «Настройки», «Точки», «Реклама» нажмите «Загрузить стартовые данные» (11 товаров SINOPEC с допусками из документов).

## E. Ограничения

- **Google Таблица как база.** Все данные и журналы в одной таблице; скорость и квоты Apps Script ограничены, при очень большом числе продаж листы будут замедляться. Параллельные записи защищены блокировкой, но это не серверная СУБД.
- **WhatsApp:** сервер ничего не отправляет. Сотрудник вручную открывает ссылку `wa.me` (напоминания, заказы, подбор). Автоматической рассылки без платных сервисов нет.
- **Telegram:** нужны токен бота и корректный `chat_id`; живая отправка в этой сборке не проверялась.
- **Офлайн:** в кэше только оболочка страниц и публичные данные (`action=public`, `action=slots`). Данные кассы и админки (запросы с токеном) и все POST не кэшируются. Продажи без сети хранятся в очереди браузера до отправки.
- **iPhone:** установка только через Safari; системного казахского языка на iPhone нет, название пункта меню Safari нужно сверить на реальном устройстве.
- **SEO и ссылки:** превью ссылок в соцсетях всегда на казахском (краулеры не выполняют JS); `openingHours` в JSON-LD берётся из свободного текста; адреса админки и кассы названы в `robots.txt`.
- **Данные:** лист Compat пуст; `desc_kk` у 11 товаров пуст (в `desc_ru` тоже пусто, ничего не придумывали).
- **Проверка:** тесты блока G ещё не запускались; код блоков A–F собран и проверен чтением и синтаксисом. Реальные iPhone и Android, живой Telegram и настоящий Apps Script не проверялись. Казахские тексты со статусом «да» в `docs/TRANSLATIONS.md` ждут проверки носителем.
- **Смены и офлайн:** при `shift_required` = `TRUE` офлайн-продажа, которую сервер отклонил с `ERR_SHIFT`, остаётся в очереди с пометкой «ждёт смену» и повторно не отправляется, пока не откроют смену; после открытия смены очередь отправляется сама.

## 4. Как работает подбор масла
Масло считается подходящим, только если у него есть **все** выбранные допуски и нужная вязкость. Допуски каждого товара хранятся в поле «Допуски» (через `;`).
Вкладка «По автомобилю» работает по листу **Compat** («Подбор: автомобили»): добавьте строку — марка, модель, годы, двигатель, требуемые допуски из руководства авто (например `ACEA C3; MB 229.51`), вязкость. ## 6. Безопасность
Пароли в таблице хранятся только как хэш SHA-256 с солью; вход выдаёт временный токен (6 часов); после 6 неверных попыток — блокировка на 10 минут; все изменения проверяются на сервере по роли. Не давайте доступ к самой Google Таблице посторонним. Двойная запись на одно время блокируется на сервере.

## Этап H — базовые интеграции и PWA (предыдущий этап; PWA не менялся в H1)

В текущей версии `admin.html` раздел «Настройки» содержит панель интеграций:
- основной `TG_CHAT_ID` можно сохранить из админки; `TG_TOKEN` никогда не выводится и задаётся только в Apps Script → Project Settings → Script Properties;
- кнопка теста отправляет проверочное сообщение; кнопка установки повторного триггера включает `tgRetry` раз в 10 минут без создания дубликатов;
- индивидуальный Telegram `chat_id` точки настраивается в разделе «Точки»; поле скрыто для не-admin и валидируется сервером;
- WhatsApp нормализуется на сервере и клиенте; подробные настройки и проверка ссылок описаны в разделе v2.19 ниже.

`assets/js/pwa.js` теперь показывает установку на Android/Chromium, подсказку для iOS Safari и баннер обновления Service Worker. После изменения файлов статического сайта версия кэша повышена до `v14`.

### Развёртывание изменений
1. Обновите файлы на GitHub Pages, сохранив структуру папок.
2. В Apps Script замените содержимое `Code.gs` этой версии и создайте **новую версию** текущего веб-развёртывания. URL `/exec` должен остаться тем же.
3. В Script Properties задайте `TG_TOKEN`; в админке откройте «Настройки», сохраните основной `chat_id`, отправьте тест и включите триггер.
4. Для отдельного Telegram-чата точки откройте «Точки» → редактирование точки → `Telegram chat_id точки`.
5. На устройствах обновите страницу дважды при подключении к интернету, чтобы получить новый Service Worker.

**Как узнать `chat_id` Telegram.** 1) Напишите любое сообщение своему боту (для группы — добавьте бота в группу и напишите там). 2) Откройте в браузере `https://api.telegram.org/bot<TOKEN>/getUpdates`, подставив токен бота вместо `<TOKEN>`. 3) В ответе найдите `"chat":{"id":...}`: это и есть `chat_id`. У группы или супергруппы id отрицательный и начинается с `-100`. Если ответ пустой (`"result":[]`), отправьте боту сообщение ещё раз и обновите страницу. Токен никому не показывайте и храните только в Script Properties (`TG_TOKEN`).

Ограничения, требующие внешней настройки: фактическая отправка Telegram не заработает без токена бота и корректного chat_id/прав бота; установка PWA требует HTTPS и поддерживаемого браузера. Список устройств входа добавлен в v2.20 (см. ниже). Offline-страница обеспечивает только оболочку; запросы к Apps Script в офлайн-режиме не выполняются.


## v2.19 — этап H1: Telegram и WhatsApp

- В админке откройте `Настройки → Интеграции`. Раздел доступен только администратору; сервер повторно проверяет роль и `manage_settings`.
- Токен Telegram добавляется вручную: Apps Script → **Настройки проекта** → **Свойства скрипта** → добавить `TG_TOKEN` со значением токена от @BotFather. Не помещайте токен в Google Таблицу, HTML, JavaScript, URL сайта или сообщения.
- Общий `TG_CHAT_ID` задаётся в интеграциях админки. Для отдельного чата точки заполните `Telegram chat_id точки` в разделе «Точки». Кнопки теста позволяют проверить общий чат и чат каждой точки. Ошибка отправки отображается в статусе; неотправленные уведомления попадают в очередь `TG_Q` и повторяются триггером `tgRetry` каждые 10 минут.
- WhatsApp: задайте общий номер и, при необходимости, отдельный номер у каждой точки. Сохраняются только цифры; для Казахстана `8XXXXXXXXXX` преобразуется в `7XXXXXXXXXX`, а 10 цифр получают префикс `7`. Допустимая длина после нормализации — 11–15 цифр. Пустой номер разрешён.
- Настройки токена никогда не читаются/записываются через API. Статус показывает только факт наличия токена, не его значение. Ошибки Telegram очищаются от URL с токеном перед записью в журнал.
- После замены `Code.gs` создайте новую версию веб-приложения Apps Script и проверьте общий/точечный тест Telegram и WhatsApp на тестовых номерах.


## v2.20 — этап H2: PWA, офлайн, устройства входа

**Установка как приложение.** `assets/js/pwa.js` один для `admin.html`, `staff.html` и `index.html`. Текст берётся из `i18n.js` на языке страницы.
- Android и десктопный Chrome: по `beforeinstallprompt` показывается кнопка «Установить приложение», по нажатию вызывается `prompt()`.
- iPhone и iPad: подсказка «Поделиться → На экран Домой» с иконкой только в Safari. В Chrome, Firefox, Edge и Opera на iOS её нет.
- Баннер не показывается в установленном приложении (`display-mode: standalone`, `navigator.standalone`). «Позже» запоминается в `localStorage` (`oh_pwa_dismissed`, в try/catch) на 7 дней.
- Баннер стоит в потоке страницы перед содержимым и ничего не перекрывает. Кнопки не ниже 44 px, работают с клавиатуры.

**Обновление.** Новый service worker даёт уведомление «Доступно обновление» и кнопку «Обновить» (`SKIP_WAITING`, затем перезагрузка). Страница перезагружается только после нажатия; первая установка service worker страницу не перезагружает. Если есть несохранённые данные, перед обновлением выводится подтверждение. Несохранёнными считаются: строки прихода в `admin.html` и в `staff.html` (черновик прихода в `localStorage` не хранится, поэтому предупреждение), а также любая изменённая форма, кроме формы входа. Корзина кассы хранится в `localStorage` (`oh_staff_draft`), очередь продаж там же (`oh_staff_queue`), поэтому для них предупреждение не требуется.

**Офлайн.** Версия кэша `v15` (`sw.js`). Без сети открывается закэшированный интерфейс, а при запросе к API выводится сообщение «Желі жоқ / Нет сети. Действие не выполнено, данные не сохранены». Введённые строки прихода остаются на экране, продажа без сети кладётся в очередь (своё сообщение) и записывается после возврата сети один раз. POST и API по-прежнему не кэшируются.

**Манифесты.** `id`, `scope`, `start_url`, `theme_color`, иконки 192, 512 и maskable есть у всех трёх. У админки имя «OilHub Admin». Проверка `Page.getInstallabilityErrors` в Chromium не находит ошибок ни у одной страницы, поэтому `scope: './admin.html'` не менялся.

**Устройства входа.** При входе в `Log` пишутся только: сотрудник, время, тип устройства (`android`, `iphone`, `ipad`, `windows`, `mac`, `linux`, `other`) и режим (`browser` или `app`). Тип и режим определяет клиент (`deviceInfo()` в `utils.js`), сервер принимает только значения из белого списка. IP, User-Agent и отпечатки не собираются и не хранятся. Действие `devices_list` доступно только admin (остальные получают `ERR_FORBIDDEN`, отказ пишется в Log). В Настройках админки блок «Устройства входа» показывает последние 5 входов на сотрудника, только просмотр. Кнопки «Закрыть сессии» нет.
